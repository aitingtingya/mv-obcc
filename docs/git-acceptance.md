# Git 集成人工验收清单

以下场景需要在 Obsidian 中手动验收（纯后端与静态检查已由 `npm run verify` 自动完成）。验收对象：`.obsidian/plugins/mv-obcc/` 中部署的 `main.js` / `styles.css` / `manifest.json`。

## 1. 设置分区

- [ ] 设置 → mv-AIDE 出现「Git」分区：分区默认折叠，Git 集成默认启用。
- [ ] 显示 Git 版本与真实仓库根目录；「重新检测」刷新结果。
- [ ] 修改「Git 可执行文件路径」为无效值后，执行任意动作报错且不破坏状态；恢复后正常。
- [ ] 「工作区位置」「diff 布局」「文件树视图」等下拉项切换立即生效。
- [ ] 在**非 Git 仓库**的 Vault 中：分区显示未初始化，提供「初始化当前 Vault」按钮；点击后可选择默认分支名并完成初始化（不会自动提交任何文件）。

## 2. 命令面板（命令面口）

- [ ] 命令面板输入 `Git:` 列出全部 Git 命令（中英文随界面语言）。
- [ ] 无目标命令（如「Git: Fetch」「Git: Pull」「Git: Push」）直接执行或弹出选择器。
- [ ] 文件类命令（如「Git: 打开 diff」）在打开笔记时自动以当前文件为目标。
- [ ] 仓库不存在时执行命令提示未初始化，而不是静默失败。
- [ ] **键盘连续操作**：Ctrl+P 执行「Git: 切换分支」后弹出模糊选择框，**打开即聚焦、直接打字过滤**，↑↓ + Enter 完成，全程无需鼠标；Esc 取消。
- [ ] 单行文本输入（如 stash 消息、分支名）以面板建议行呈现：打开即聚焦并预填默认值，Enter 提交已输入内容，留空时显示「（留空）」可提交空值。
- [ ] **从命令面板**执行「Git: 暂存全部并提交推送」等需要提交消息的命令：消息输入为面板建议行（单行），**不再弹出窗口**；从工作区提交框发起时仍为多行文本域。
- [ ] **从命令面板**触发的任何确认（含破坏性操作、批量 cherry-pick 顺序预览）都在面板内以「确认／取消」两项呈现，确认项下方展示明细；Enter 选择、Esc 取消。
- [ ] 工作区入口的确认对话框打开即聚焦「确认」按钮：Enter 确认、Esc 取消。

## 3. 工作区面板

- [ ] 工作区入口：命令「Git: 打开工作区」、文件右键菜单「Git…」、状态栏 Git 状态点击均可打开工作区；工作区可停靠左/右栏或作为完整标签页。
- [ ] 状态分为「已暂存」「工作区」「未跟踪」「冲突」四组；目录可折叠（文件树视图开/关两种模式）。
- [ ] 工作区顶部工具条依次为「推送」「获取」「拉取」「抓取」四个按钮加「…」全部操作菜单；「获取」执行 `git fetch --all`（下载远端全部分支、不改动工作区），「抓取」选择单个远程抓取；「刷新」「同步」从工具条移除，但在「…」菜单与命令面板中仍可执行。
- [ ] 分区默认展开状态：已暂存、冲突展开；未暂存、未跟踪、提交历史默认折叠，手动展开后在当前视图实例存活期内保持（视图重建后回到默认）。
- [ ] 分区自上而下顺序：文件分组 → 分支 → 提交历史 → 标签 → 工作进度 → 远程（最下）。
- [ ] 「未暂存」分组按钮行依次为「暂存文件」「暂存全部改动」「丢弃文件修改」；「暂存全部改动」把含未跟踪在内的全部改动入暂存区。
- [ ] 底部提交框：输入消息 → 提交按钮 / Ctrl+Enter 提交；下拉菜单含「提交」「暂存全部并提交」「暂存全部并提交推送」「提交并推送」「提交并同步」「修改最新提交」「撤销最新提交」；从下拉执行过某动作后，主按钮文案变为该动作并随布局保持，Ctrl+Enter 同步执行该动作。
- [ ] 命令面板存在「Git: 暂存全部并提交推送」并一次完成暂存+提交+推送；推送失败时提交保留且错误气泡注明部分成功。
- [ ] 提交历史区可拖拽调整高度（布局在视图状态间保持）；提交图连线正确。
- [ ] 历史行显示哈希、标题、分支/标签徽章（当前分支高亮、tag 样式区分）与绝对时间（yyyy-MM-dd HH:mm）。
- [ ] 历史区头部「选择分支」按钮弹出菜单：当前分支 / 全部分支 / 每个本地与远程分支（当前项带 ✓）；选择后历史只显示该分支可达提交；**选择持久保存**——重开工作区、重启 Obsidian 后仍是所选分支（仅当该分支被删除时才回退当前分支）。
- [ ] 提交成功（含「暂存全部并提交」「提交并推送」等全族）后消息框自动清空并恢复为模板；提交失败或在确认框取消时草稿保留。
- [ ] 分支区任一分支（含远程分支）右键菜单**首项**为「查看提交历史」：历史区展开、过滤到该分支并滚动到历史区。
- [ ] 勾选框默认隐藏；点击「节点批量操作」按钮后出现，再次点击隐藏并清空选择。勾选 ≥2 个提交后右键出现「批量 cherry-pick」「批量 revert」；确认对话框中预览顺序为旧→新，与界面选择顺序无关。
- [ ] 键盘：行内 ↑↓ 移动、Enter 打开、右键菜单键 / Shift+F10 弹出菜单。

## 3.1 操作结果通知

- [ ] 关闭 Git 工作区面板后，从命令面板执行「Git: 提交暂存的更改」等写操作：成功时右上角弹出成功气泡（提交族动作带新提交短哈希）。
- [ ] 失败（如 hooks 拒绝、推送冲突）弹出错误气泡，内容包含真实 Git 错误与部分成功信息。
- [ ] 只读动作（打开 diff、复制 SHA、查看 reflog）不弹气泡。
- [ ] 设置 → Git → 「操作结果通知」关闭后成功气泡不再出现，失败气泡仍然出现。
- [ ] 在确认对话框中取消破坏性操作（如丢弃）不弹任何气泡。

## 4. Diff 视图

- [ ] 「diff 打开位置」默认「中间主区」：从工作区（即使工作区在右侧栏分屏下部）打开 diff 时，diff 出现在主区新标签页。
- [ ] 切换到「沿 Git 工作区分屏」后 diff 出现在工作区旁；「右侧栏」「左侧栏」分别落入对应侧栏。
- [ ] 冲突编辑器遵循同一设置。

- [ ] 工作区文件 diff：并排/行内切换；勾选 diff 下方复选框选中行/差异块后可「暂存选中部分」；工作区一侧可直接编辑并保存。
- [ ] 暂存文件 diff 支持「取消暂存选中部分」。
- [ ] 在 diff 打开期间于外部（终端）修改同一文件：保存被阻止并提示外部变更，草稿保留。
- [ ] 索引在外部变化后，行级暂存被拒绝并提示重新读取。

## 5. 冲突解决

- [ ] 制造 merge 冲突后，「冲突」组出现文件；打开进入三方编辑器：左侧 ours（只读，标注真实来源）、右侧为工作区结果（可编辑），基线与 theirs 在折叠区。
- [ ] rebase 冲突中左侧标注「HEAD（变基目标侧）」、theirs 标注「正在回放的提交」，与 git 语义一致。
- [ ] 「保存」与「标记已解决」是两个独立按钮；全部解决后「继续」完成 merge。
- [ ] 「中止」恢复操作前状态。

## 6. 引用区（分支/标签/stash/远程）

- [ ] 分支区：当前分支高亮；右键含切换/重命名/删除/设上游/发布/合并/变基。
- [ ] 标签区：创建轻量与附注标签（附注可填消息）；删除本地与远程标签均有确认。
- [ ] stash 区：新建（可选含未跟踪/仅暂存）、查看、应用、弹出、删除、从 stash 建分支。
- [ ] 远程区：添加/修改/重命名/删除远程；抓取、清理失效引用；远程分支右键检出跟踪分支。

## 7. 历史与恢复

- [ ] 提交节点右键：详情、变更文件、四种比较、复制 SHA/消息、检出（有 detached HEAD 提示）、建分支/标签、cherry-pick、revert、reset（三档附说明）、重置当前分支到此处并重载 Obsidian（确认后先重置、成功才重载，取消不重置不重载）、合并、变基到此处。
- [ ] 「Git: 查看 reflog」列出记录；从记录创建恢复分支可找回丢失提交。

## 8. 状态栏与编辑器

- [ ] 状态栏显示分支与领先/落后；点击打开工作区；在设置中可关闭。
- [ ] 开启「编辑器修改标记」后，编辑区行号槽出现添加/修改/删除标记（相对 HEAD）。
- [ ] 开启「当前行归属提示」后，光标行行尾显示最近提交摘要；未提交的行不显示。

## 9. 多窗口

- [ ] 主窗口与弹出窗口各自打开 Git 工作区，选中集互不覆盖。
- [ ] 在弹出窗口发起的对话框出现在弹出窗口，不回主窗口。

## 10. 平台说明

- macOS：本次开发已实测。
- Windows / Linux：未实测，按平台支持矩阵标注为「需对应平台验收」。
